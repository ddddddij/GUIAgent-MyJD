# MyJD 项目架构分析文档

## 1. 项目概述

**项目名称**: MyJD (京东商城模拟应用)
**包名**: com.example.myjd
**技术栈**:
- Kotlin
- Jetpack Compose
- Android MVVM架构（部分实现）
- Gson (JSON序列化)
- Coil (图片加载)
- Navigation Compose (导航)

**架构模式**: 混合架构（目标MVVM，但未完全符合标准）

## 4. 架构问题详细清单

### 严重问题（❌ 必须修复）

#### 问题1: 缺少依赖注入（DI）系统
**描述**: 项目没有配置Hilt或Dagger
**影响范围**:
- `MainActivity.kt` (第46行): `val repository = remember { DataRepository.getInstance(context) }`
- `HomeScreen.kt` (第26行): 同样直接创建Repository
- 所有Screen和ViewModel手动管理依赖

**违反规范**: MVVM架构要求第4条 - ViewModel需要使用`@HiltViewModel`注解
**改进建议**:
1. 在`build.gradle.kts`添加Hilt依赖
2. 创建`di/AppModule.kt`配置DI
3. MainActivity使用`@AndroidEntryPoint`
4. ViewModel使用`@HiltViewModel`和`@Inject`
5. 删除所有ViewModelFactory

#### 问题2: 目录结构不符合MVVM标准
**描述**: data/、domain/目录为空，实际代码在根目录
**违反规范**: MVVM架构要求第1条 - 项目结构标准
**改进建议**:
1. 移动`model/`到`domain/model/`
2. 拆分`repository/DataRepository.kt`：
   - 创建`domain/repository/DataRepository.kt`接口
   - 重命名为`data/repository/DataRepositoryImpl.kt`实现
3. 考虑添加`data/mapper/`进行数据转换
4. 考虑添加`data/local/`管理本地数据源

#### 问题3: ViewModel创建方式不规范
**描述**: 使用手动ViewModelFactory而非DI
**影响文件**:
- `ViewModelFactory.kt`
- `SearchResultViewModelFactory.kt`
- `ShopViewModelFactory.kt`

**违反规范**: MVVM架构要求第4条
**改进建议**: 引入Hilt后删除所有Factory，改用`@HiltViewModel`

#### 问题4: UI层直接调用Repository
**描述**: CartScreen和ProductSpecDialog直接调用repository方法
**影响文件**:
- `CartScreen.kt`: 直接调用11个repository方法
- `ProductSpecDialog.kt`: 直接调用`repository.loadProductDetail()`

**违反规范**: MVVM架构要求第5条 - 在Composable里直接调用Repository
**改进建议**: 所有数据操作必须通过ViewModel，UI层只负责展示

#### 问题5: Repository设计不符合标准
**描述**: DataRepository既是接口又是实现，没有分离
**违反规范**: MVVM架构要求第2.3条 - Repository应分为接口和实现
**改进建议**: 参考问题2的改进方案
