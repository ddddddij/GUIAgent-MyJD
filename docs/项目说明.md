## 1) 数据文件如何保存

首先，包含两层数据，静态数据保存在Assets中，动态数据（例如购物车、订单、消息）存在内部存储的JSON文件中，支持增删改查

### 数据存储架构
```
├── 第一层: Assets静态资源 (只读)
│   ├── 应用初始数据
│   ├── 商品和店铺信息
│   └── 预置消息和订单数据
└── 第二层: 内部存储文件 (可读写)
    ├── 用户添加的购物车数据
    ├── 用户创建的订单数据
    ├── 用户发送的消息数据
    └── 其他用户操作产生的数据
```

### 动态数据存储 (内部存储)

存储位置可以参考`DataRepository.kt`


### 数据读取优先级策略

```kotlin
// 数据读取流程
1. 优先从内部存储读取 (包含用户新数据)
   ↓ (如果文件存在)
2. 回退到Assets静态数据
   ↓ (如果内部存储不存在)
3. 加载Assets默认数据并初始化内部存储
```

### 数据变化流程

以添加商品到购物车为例，其流程如下:

```
用户点击加购 → 创建CartItemSpec对象 → 添加到购物车列表 → 保存到内部存储
```

1. **触发**: 用户在商品详情页点击加入购物车
2. **处理流程**:
   ```
   HomeViewModel.addToCart()
   ↓
   创建CartItemSpec对象(包含商品ID、规格、数量等)
   ↓
   DataRepository.addToSpecCart()
   ↓
   读取现有cart_items.json → 添加新商品 → 写回文件 → 更新StateFlow
   ```
3. **结果**: 购物车立即显示新商品，重启应用后仍然保留

### 负责数据保存的核心类: DataRepository

```kotlin
class DataRepository private constructor(private val context: Context) {
    private val gson = GsonBuilder()
        .setPrettyPrinting()
        .create()

    // 单例模式
    companion object {
        @Volatile
        private var INSTANCE: DataRepository? = null

        fun getInstance(context: Context): DataRepository {
            return INSTANCE ?: synchronized(this) {
                INSTANCE ?: DataRepository(context.applicationContext).also {
                    INSTANCE = it
                }
            }
        }
    }

    // 主要职责:
    // 1. 资源加载 - 从assets JSON加载初始数据
    // 2. 持久化存储 - 将数据保存到内部存储
    // 3. 数据查询 - 提供各类型数据的查询接口
    // 4. 状态管理 - 使用StateFlow响应式更新数据
}
```

## 2) Model读取进来之后是什么样的数据类型

### 一、核心数据模型层 (domain/model/)

以Product (商品模型)为例

**位置**：`app/src/main/java/com/example/jd_sim/domain/model/Product.kt`

```kotlin
data class Product(
    val id: String,                // 商品ID (eg. "p_001")
    val name: String,              // 商品名称 (eg. "Apple iPhone 15 128GB 黑色")
    val price: Double,             // 当前价格 (eg. 5999.0)
    val originalPrice: Double? = null,  // 原价 (eg. 6999.0)
    val brand: String,             // 品牌 (eg. "Apple")
    val category: String,          // 分类 (eg. "手机")
    val imageUrl: String,          // 图片路径 (eg. "image/iPhone15封面.JPG")
    val storeId: String,           // 店铺ID (eg. "store_apple")
    val storeName: String,         // 店铺名称 (eg. "Apple京东自营旗舰店")
    val colors: List<String> = emptyList(),      // 可选颜色
    val versions: List<String> = emptyList(),    // 可选版本
    val selectedColor: String? = null,           // 已选颜色
    val selectedVersion: String? = null,         // 已选版本
    val stock: Int = 0,            // 库存数量
    val isInStock: Boolean = true, // 是否有货
    val rating: Float = 0f,        // 评分 (eg. 4.8f)
    val reviewCount: Int = 0,      // 评价数量
    val description: String = "",  // 商品描述
    val specifications: Map<String, String> = emptyMap() // 规格参数
)
```

- **数据来源**：products.json -> products数组
- **实例数量**：products.json中定义的所有商品

其他数据类型均保存在`app/src/main/java/com/example/jd_sim/domain/model`中

## 3) MVVM中的V和VM，在执行动作的时候，页面和数据如何变化

项目采用MVVM架构，View(V)负责UI展示和用户交互，ViewModel(VM)负责业务逻辑处理和数据管理。当用户在页面上执行操作时，会触发V→VM→Repository→V的完整数据流循环，实现页面状态的响应式更新。

### 一、核心交互流程
```
用户操作 → View回调 → ViewModel处理 → Repository数据变更 → StateFlow发布 → View状态更新 → UI重新渲染
```

### 三、数据流动的完整时序图

#### 1. 添加购物车场景时序
```
用户 → View → ViewModel → Repository → File System
 |      |        |           |           |
 |      |        |           |           |- 保存cart_items.json
 |      |        |           |- addToSpecCart()
 |      |        |- addToCart()
 |      |- onClick callback
 |- 点击加购按钮

File System → Repository → StateFlow → ViewModel → View → UI
     |           |           |          |          |      |
     |           |           |          |          |      |- 购物车显示新商品
     |           |           |          |          |- collectAsState()
     |           |           |          |- specCartFlow
     |           |           |- emit(newList)
     |           |- _specCartFlow.value = newList
     |- 持久化完成
```

#### 2. 页面状态变化时间线
```
T0: 用户点击加购 (点击事件)
    - onClick触发
    - viewModel.addToCart()

T1: ViewModel开始处理 (+5ms)
    - 创建CartItemSpec对象
    - 调用repository.addToSpecCart()

T2: Repository更新数据 (+15ms)
    - 添加到内存列表
    - 保存到文件系统
    - 更新StateFlow

T3: StateFlow发布变化 (+20ms)
    - emit新的购物车列表
    - 通知所有订阅者

T4: View收到通知 (+25ms)
    - collectAsState检测到变化
    - 触发Compose重组

T5: UI重新渲染 (+30ms)
    - 购物车列表重新绘制
    - 显示新添加的商品
    - 更新底部导航红点
```

### 四、MVVM架构的优势体现

1. **单向数据流**：
   ```
   User Action → ViewModel → Repository → StateFlow → UI
   ```

2. **响应式更新**：
   - 使用StateFlow自动通知UI更新
   - 无需手动调用UI刷新方法

3. **生命周期安全**：
   - StateFlow自动处理生命周期
   - 避免内存泄漏

4. **数据持久化**：
   - Repository统一管理数据存储
   - ViewModel无需关心存储细节

5. **可测试性**：
   - ViewModel可独立测试
   - Repository可以mock
